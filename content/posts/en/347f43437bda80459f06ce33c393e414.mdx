## What is react-hook-form?


[https://react-hook-form.com/](https://react-hook-form.com/)
First, react-hook-form is a library that efficiently manages form data states and significantly reduces the amount of code.
(It's also a key library used by [Toss](https://tosspayments-dev.oopy.io/cc9367e4-4ff6-4241-8189-9f3cf250f5d2).)


## When is it used?


It can be used in any scenario where a user handles JSON data through an event. For states managed as objects, you might not even need to use `useState` or `useReducer`.
e.g., all information input and modification, filter search functionality, user registration, login, etc.

### Form Management using useState

- container

```typescript
const Container = React.memo(function Container() {
  const [state, setState] = React.useState({ email: '', password: '' });
  const [errorMessage, setErrorMessage] = React.useState<{ email: null | string; password: null | string }>({
    email: null,
    password: null,
  });

  return (
    <VStack gap={1} width={'100%'}>
      <Typography variant="Title_Looko">로그인 정보</Typography>

      <EmailForm state={state} setState={setState} errorMessage={errorMessage} setErrorMessage={setErrorMessage} />
      <PasswordForm state={state} setState={setState} errorMessage={errorMessage} setErrorMessage={setErrorMessage} />

      <Button onClick={() => {
        	//... state 핸들링
        }} color="primary" variant="contained">
        다음
      </Button>
    </VStack>
  );
});
```

- email input

```typescript
const EmailForm = ({
  state,
  setState,
  errorMessage,
  setErrorMessage,
}: {
  state: {
    email: string;
    password: string;
  };
  setState: React.Dispatch<
    React.SetStateAction<{
      email: string;
      password: string;
    }>
  >;
  errorMessage: {
    email: null | string;
    password: null | string;
  };
  setErrorMessage: React.Dispatch<
    React.SetStateAction<{
      email: null | string;
      password: null | string;
    }>
  >;
}) => {
  return (
    <FormRow
      label="이메일"
      inputComponent={
        <Input
          error={!!errorMessage.email}
          value={state.email}
          onChange={e => {
            const value = e.target.value;
            if (!value) {
              setErrorMessage(prev => ({ ...prev, email: '이메일을 입력해주세요' }));
              return;
            }

            if (!isValidEmail(value)) {
              //유효한 email인지 validation 하는 함수
              setErrorMessage(prev => ({ ...prev, email: '유효한 이메일 주소를 입력해주세요' }));
              return;
            }

            setErrorMessage(prev => ({ ...prev, email: null }));
            setState(prev => ({ ...prev, email: e.target.value }));
          }}
        />
      }
      errorMessage={errorMessage.email}
    />
  );
};
```

Voila! A very long piece of code is complete.
It was really difficult to write, from passing many `props` to handling errors...
Despite the effort, there are also performance issues.


Since `useState` is used to manage the object, even just changing the password causes continuous re-rendering of both the **Container** component and the **EmailForm** component.

If this phenomenon occurs with data where forms are in a list... it would lead to truly terrible performance.


### Form Management using react-hook-form

- Container

```typescript
const Container = React.memo(function Container() {
  const methods = useForm<{ email: string; password: string }>();

  return (
    <VStack gap={1} width={'100%'}>
      <form
        onSubmit={methods.handleSubmit(v => {
          // 데이터 핸들링
        })}
      >
        <FormProvider {...methods}>
          <EmailForm />
          <PasswordForm />
        </FormProvider>
      </form>
    </VStack>
  );
});
```

- EmailForm

```typescript
const EmailForm = () => {
  const {
    register,
    formState: { errors },
  } = useFormContext<{ email: string }>();
  return (
    <FormRow
      label="이메일"
      inputComponent={
        <Input
          {...register('email', {
            required: '이메일을 입력해주세요',
            validate: v => isValidEmail(v) || '유효한 이메일 주소를 입력해주세요',
          })}
        />
      }
      errorMessage={errors.email?.message}
    />
  );
};
```

- PasswordForm

```typescript
const PasswordForm = () => {
  const {
    register,
    formState: { errors },
  } = useFormContext<{ password: string }>();
  return (
    <FormRow
      label="이메일"
      inputComponent={
        <Input
          {...register('password', {
            required: '비밀번호를 입력해주세요',
            validate: v => isValidPassword(v) || '8자~16자의 영문, 숫자, 특수문자를 사용해주세요',
          })}
        />
      }
      errorMessage={errors.password?.message}
    />
  );
};
```


It seems to have taken less than a tenth of the time compared to writing the `useState` example above.
It's really simple, isn't it? Can you see how much the code has been reduced?
The amount of code when managing numerous form data with `state` was truly dreadful.


Furthermore, react hook form handles components as uncontrolled components, optimizing rendering.

- *Code size, rendering, `props drilling` **
Simply using react-hook-form significantly lowers code complexity and optimizes performance.

## What Problems Were Solved?


**1. Reduced Code Fragmentation**
By not using `store`, `context`, `atom`, etc., code fragmentation was minimized. (The example code above used `props`, but this also applies to cases using `store` and `context`.)


**2. Separation of Concerns**
Code modifications in other places were eliminated, regardless of whether other components were removed or added.


**3. Eliminated Unnecessary Rerenders**
It optimizes rendering by being composed of uncontrolled components.


**4. Increased Maintainability**
With a significant reduction in code, understanding the logic became much easier during code reviews or when revisiting the code.


## Conclusion


react-hook-form is a fantastic library that can handle all form-related scenarios in `react` and `react-native`.
